## 一、为什么做它

学中医的人大概都遇到过同一组麻烦：

- 想查一条《伤寒论》原文，得在几个 App、网页、PDF 之间来回翻；
- 读到一则医案想做批注，笔记散在备忘录里，和原文对不上；
- 想让大模型帮忙解读，又不敢把整本资料库、自己的笔记一股脑传上去；
- 断网的时候，什么都用不了。

「青禾医理」想解决的就是这四件事：**书要全、要能读能批注、要能检索、要能借助 AI，但数据始终留在本机。**

名字取「青禾」——禾苗初生，对应中医里生发、草木、东方木的意象；「医理」则提醒自己，这是个研习医理的工具，不是诊断工具。

## 二、一条红线：书在本机，云只是外脑

架构上只守一条原则：

```
┌──────────────────────────── 手机 / 桌面本机 ────────────────────────────┐
│  tcm.db   只读分发：古籍白文全本 + 结构化索引 + FTS5 双索引             │
│  user.db  ATTACH 进来的可写库：收藏 / 批注 / 笔记 / 对话 / 每日卦象缓存 │
│                                                                        │
│  Repository ── 本地检索 ──> 裁剪后的片段 ──> [可选] 发给 LLM           │
└────────────────────────────────────────────────────────────────────────┘
                                      │ 只发片段，不发整库
                                      ▼
                          DeepSeek API（用户自配密钥）
```

具体边界：

| 内容 | 是否出本机 |
|---|---|
| 古籍白文（公有领域） | 仅召回片段，可外发 |
| 结构化索引（条文 / 本草 / 方剂 / 经脉 / 穴位） | 仅召回片段，可外发 |
| 倪师医案原文 | **默认不外发** |
| 医案「RAG 分析此案」 | **只外发「主诉 + 处方摘要」**，不含现病史、剂量、按语 |
| 用户笔记、收藏、批注、对话历史 | **绝不外发** |
| 密钥 | 运行时写入系统安全存储，不写进工程、不编译进二进制 |

没有配密钥时，App **完全离线**，`ask()` 直接返回本地检索结果，不发起任何网络请求。云端失败也一律降级回本地结果，不阻塞阅读。

## 三、技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 客户端 | Flutter 3.x（Dart） | 一套代码覆盖 Android / 桌面；自绘 UI 不依赖组件库 |
| 本地库 | `sqlite3` FFI + `sqlite3_flutter_libs` | 真 SQLite，不是对象包装；FTS5 可用 |
| 全文检索 | FTS5「按字切分 phrase」+ trigram 补充 | 中文没有空格，按字切分能召回「柴胡」这类词 |
| 状态 | 自带 `ValueNotifier` / `InheritedNotifier` | 依赖刻意保持最小 |
| LLM | DeepSeek `deepseek-flash`（OpenAI 兼容接口） | 可插拔预设，换 base_url / model / key 即可 |
| 密钥 | `flutter_secure_storage` | Android Keystore / iOS Keychain |
| UI | 全自绘 `CustomPaint` + 内联 SVG | 五行罗盘、八卦环都是代码画的 |

**为什么不用云数据库 / 后端？** 因为这个项目的核心卖点就是「资料库不上传」。本机 SQLite 加 ATTACH 已经足够，多一个服务端反而多一份风险。

## 四、数据层：两个库、七部全本、79 条索引

### 4.1 两个库

- `prototype/tcm.db`：源库，ETL 脚本往这里灌数据；
- `tcm_app/assets/db/tcm.db`：随 App 分发的只读库，内容与源库逐表一致；
- `prototype/user.db`：本机可写库，通过 `ATTACH` 挂载，升级资料库时**永不覆盖**。

两库当前各表行数一致，`PRAGMA integrity_check` 均为 `ok`。

### 4.2 七部公有领域白文全本（8164 条）

| 书 | 朝代 / 作者 | 条文数 |
|---|---|---|
| 伤寒论 | 东汉 · 张仲景 | 398 |
| 金匮要略方论 | 东汉 · 张仲景 | 520 |
| 黄帝内经素问 | 唐 · 王冰次注 | 514 |
| 神农本草经 | 清 · 孙星衍辑 | 486 |
| 景岳全书 | 明 · 张介宾 | 4850 |
| 四圣心源 | 清 · 黄元御 | 344 |
| 周易 | 周 · 姬昌 / 战国 · 十翼 | 1052 |

《周易》按通行王弼本经传白文整理，六十四卦齐全 + 系辞 / 说卦 / 序卦 / 杂卦（69 篇），并给「阴阳、元亨利贞、自强不息」等核心词补了简体检索增强，方便用简体查繁体底本。

所有白文均取自著作权保护期届满的文本；**主动排除**了 1980 年现代排印本《桂林古本》——古籍白文是公有领域，但现代点校、注释、白话译文另受版权保护，这条线不能混。

### 4.3 79 条结构化资料

除全本之外，库里还有一批便于查询学习的索引级资料，全部汇进金页「资料速查」：

| 类 | 表 | 条数 | 能看到什么 |
|---|---|---|---|
| 经典条文 | `classics` | 18 | 四部经典精选、篇卷、条文号 |
| 本草 | `herbs` | 8 | 《神农本草经》原文、性味、归经、功效 |
| 方剂 | `formulas` | 5 | 经典出处、组成、主治、剂量、煎服法 |
| 十二正经 | `meridians` | 12 | 五行、脏腑、六经、循行概要 |
| 穴位 | `acupoints` | 32 | 穴名、代码、归经、特定穴、定位 |
| 六经证型 | `syndromes` | 4 | 定义、辨证要点 |

这里有个**必须说清楚的诚实边界**：这些结构化表在 `meta.dataset` 里标的是 `DEMO / 结构演示数据`，`ni_commentary` 大多是「（演示占位）」。导出时统一清洗了占位前缀，但一律标注「注解 · 演示」，**没有冒充真实倪师注解**；穴位也不含针刺深度与手法，只作归经与文献温习索引。

统一字段由 `prototype/export_materials.py` 从数据库导出：

```python
# 幂等：重复运行覆盖 materials.json 与 HTML 内嵌常量
python prototype/export_materials.py
# 输出：classic 18 / herb 8 / formula 5 / meridian 12 / acupoint 32 / syndrome 4
```

Flutter 端由 `repository.materials({query, kind})` 实时读同一批表，与预览页内嵌的 `MATERIALS` 字段完全一致——**预览页看到的，就是 App 里查到的**。

## 五、五行不是装饰：五个入口怎么切

用户的一句话定了信息架构：「万物不出五行」。底部导航不是五个功能模块，而是同一份本地库的五种取用角度：

| 位 | 行 | 页面 | 取义 | 主要动作 |
|---|---|---|---|---|
| 0 | 木 | 医案研读 | 生发 · 临证生机 | 六经 / 病症 / 方剂三维分类；RAG 分析此案 |
| 1 | 火 | 罗盘推演 | 神明 · 洞察取象 | 五行八卦罗盘；点卦 / 点行生成提问 |
| **2** | **水** | **玄思研习（C 位）** | **润下 · 主智** | **RAG 对话 + 参考溯源** |
| 3 | 金 | 方药古籍库 | 收敛 · 成文定本 | 7 部书架 + 79 条资料速查 |
| 4 | 土 | 灵笈 | 承载 · 我的积累 | 笔记 / 收藏 / 历史 / 设置 |

水放正中是刻意的：问答是全库的入口，也是核心页。相生序不强加给导航，只用于罗盘流光与底部细轨；色板通过 `Ink.tabElements = [0,1,4,3,2]` 映射，所以水在正中依然是水的玄色。

跨页携带上下文用 `PendingQuery + WuxingNavController.submit()`，`NavScope` 挂在 `MaterialApp` 之外（Navigator 之上），因此 `Navigator.push` 出来的详情页也能读到上下文。

配色定名「玄夜观星」：深墨青夜空 `#162C31`、宣纸米黄 `#F1E7D0`、暗金星轨 `#C9A45C`，五行色沿用木绿 / 火赤 / 土金 / 金属白 / 水蓝。

## 六、RAG 怎么做到不瞎编（一次事故复盘）

### 事故

早期版本有个真实反馈：**「我问针灸，它给我回答伤寒」**。

查下来不是模型幻觉，是检索层的锅：

```dart
// 旧实现：检索为空时「兜底」取前 N 条
if (hits.isEmpty) {
  rows = _repo.searchClassics('', limit: 6);  // 空串 → 恰好都是《伤寒论》开头几条
}
```

再加一层：预览页的 `send()` 干脆把答案写死成《伤寒论》第 96 条 / 小柴胡汤。于是无论问什么，prompt 里都躺着伤寒条文，模型只能围绕伤寒作答。

### 修复

1. **删掉所有「凑数」兜底**。检索不到就诚实返回空，绝不拿不相关条文填 prompt。
2. **检索链路补全**：依次查 `classic_fts` 全本 → 早期 `classics` → 经脉 / 穴位索引 → 医案 FTS；命中经络域词（针、灸、穴、经络、俞、募……）时补 `meridians` / `acupoints`。
3. **预览页明确标注演示模式**：`本页不联网、不调用 DeepSeek；回答 = 内嵌公有领域语料的本地检索结果`，并展示真实检索到的片段与 `[S#]` 引用。
4. **中文检索不用任意单字兜底**：改成整词 + 词面扩展 + 领域词表，避免「量子力学」因「子」「学」命中一堆伤寒条文。
5. **引用校验**：只允许引用实际发出去的 `[S#]` 编号，并抓取裸条文号，防模型编造依据。

实测结果：

| 提问 | 召回 |
|---|---|
| 针灸 | 4 条真实条文（伤寒第 8 条「针足阳明」、金匮「针灸膏摩」等）+ 经脉索引 |
| 桂枝汤 | 伤寒第 12 条 |
| 上工治未病 | 金匮第 1 条 + 素问「四气调神大论」 |
| 乾卦 | 《周易》乾卦经文 4 条 |
| 量子力学 | **0 条，走诚实兜底** |

### DeepSeek Flash 的两个坑

`deepseek-flash` 是推理模型，实测踩过：

- 只给 `max_tokens` 太小，返回的 `content` 是空的，内容全在 `reasoning_content` 里——必须给足预算；
- 控制推理开销的参数是 `effort: "low"`，不是 `reasoning_effort`；推理 token 也计入 `completion_tokens` 计费。

代码里把这些写死在 preset 里，避免后续换模型时再踩一次。

## 七、每日一卦、基础温习与古风立绘

- **每日一卦**：六十四卦 8×8 方阵，按日期确定性生成上下卦与动爻，同一天恒定、跨天必变；按 `YYYY-MM-DD` 缓存进 `user.daily_gua`。卦象解读由 AI 生成但只带结构信息，明确标注「传统取象 / 文化层面的理解」，不索取 `[S#]`、不给剂量，失败降级为本地文案。
- **基础温习**：单独一页（不占五行导航），放今日一条、十二正经、常用穴位、经典条文，全部本地离线。
- **古风立绘**：两张二次元水墨人物（女医者 / 少年托罗盘）装饰页面，八卦与五行环是内联 SVG / `CustomPaint`，不额外增加图片体积。

火页的罗盘按参考八卦图重绘过：宣纸米黄实底大圆盘、外圈金色光点、8 条弧形卦名 `<textPath>`、8 组三爻、中心黑白太极、48 刻度、五行节点。

## 九、本地跑起来

### 环境

- Flutter SDK：`D:\dev\flutter`
- Android SDK：`D:\dev\android-sdk`（android-35 / 36，build-tools 35 / 36）
- JDK：`D:\dev\jdk`
- 本项目用 `tcm-app.code-workspace` 一次打开三个文件夹（总览 / `tcm_app` / `prototype`）

### 三条路径

**1. 最快看效果（零依赖）**：直接用浏览器打开根目录 `五行交互UI预览.html`。七页可点：五行五页 + 基础温习 + 离线古籍，含今日一卦、罗盘、跨页携带提问与参考溯源。纯静态、零联网，回答是演示数据。

**2. 跑 Flutter**：

```bash
cd tcm_app
flutter pub get
flutter run
```

**3. 校验与打包**：

```bash
flutter analyze        # 0 issue
flutter test           # 34 / 34
flutter build apk --release
# 产物：build/app/outputs/flutter-apk/app-release.apk
```

Windows 下若 `flutter` 在 Git Bash 里触发环境异常，用 Python subprocess 调 `flutter.bat` 并补齐 `JAVA_HOME` / `ANDROID_HOME` / `APPDATA` 等变量即可（项目里备了本机校验脚本）。

还有一个 Windows 专属坑：工程路径里只要含中文（比如 `C:\Users\墨鱼\...`），Android Gradle Plugin 会直接拒绝打包：

```
Your project path contains non-ASCII characters.
This will most likely cause the build to fail on Windows.
Please move your project to a different directory.
```

这个坑实测有**两层**：

第一层是 AGP 的路径检查，可以在 `tcm_app/android/gradle.properties` 关掉：

```properties
android.overridePathCheck=true
```

但关掉之后还有第二层：Kotlin 编译器的增量缓存同样会因路径乱码损坏，报

```
Could not close incremental caches ...
:shared_preferences_android:compileReleaseKotlin
```

这个开关救不了。**Windows 上最稳妥的做法是把工程复制到纯 ASCII 路径再构建**，
产物再拷回原工程（项目里已备好本机脚本）：

```python
# 排除 build / .dart_tool 后复制，避免把损坏的缓存一起带过去
shutil.copytree(src, r"D:\dev\qinghe_build\tcm_app",
                ignore=shutil.ignore_patterns("build", ".dart_tool"))
```

```bash
cd D:\dev\qinghe_build\tcm_app
flutter build apk --release
# 产物：build/app/outputs/flutter-apk/app-release.apk
```

顺带一提：改过 `pubspec.yaml` 的 assets 后，打包别加 `--no-pub`，
否则 `AssetManifest` 不刷新，新加的资源不会进 APK。
原生桌面开发（Windows / macOS）不受这个路径限制影响。

### 想让 AI 真正联网

预览页**永远不联网**。真实 App 需要二选一：

- VSCode 调试：设环境变量 `DEEPSEEK_API_KEY`，`launch.json` / `tasks.json` 已接 `--dart-define`；
- 运行时：App「土 · 灵笈 → 设置 → API 密钥」粘贴，写入系统安全存储。

水页状态条会显示密钥是否就绪。**明文 key 不要写进工程文件**。

## 十、合规与边界

| 项 | 处理 |

| 医疗定位 | 文献检索与学习工具；**不诊断、不开方、不提供剂量** |
| 高风险方剂 | 剂量隐藏，提示咨询执业中医师 |
| 个人学习 / 免费开源 | 可行（须署名）；**收费上架 / 商业化必须先取得授权** |

结构化资料为演示级索引，不作诊疗依据；穴位内容只作归经与文献温习索引，不含针刺操作参数。

## 十一、路线图

1. 导入真实医案库（`prototype/import_tcm_db.py`），替换 4 则演示医案，重建双索引并升 `bundledDataVersion`；

5. 补齐 iOS / 桌面端签名与分发配置。

## 结语

做一个「能离线读、能查、能批注、能问」的中医 App，技术上并不玄乎：一个 SQLite、一套 FTS5、一层克制的 RAG。难的是**守住边界**——哪些内容能出本机、哪些注解不能冒充真、检索不到时要不要诚实地说「没找到」。

青禾医理目前仍是一个个人研习工具，资料库里的医案还是演示数据。但它已经把骨架立住了：**书在你手里，云只是偶尔借来的外脑。**
